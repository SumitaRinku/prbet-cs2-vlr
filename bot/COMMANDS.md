# QQ 群竞猜、账号绑定和结算推送

## 1. Linux 网站配置

先备份数据库，部署本次项目代码。在网站 `.env` 增加：

```dotenv
BOT_COMMAND_GROUP_IDS=123456789,987654321
BOT_ADMIN_QQ_IDS=你的管理员QQ号,另一个管理员QQ号
```

`BOT_COMMAND_GROUP_IDS` 为允许群指令和结算通知的群号；`BOT_ADMIN_QQ_IDS` 为具有网站赛事管理权限的 QQ 号。多个号码以英文逗号分隔，不加引号；示例文字需替换为真实数字。不填群名单则功能关闭，不填管理员名单则任何 QQ 都不能运行管理指令。权限由网站验证，QQ 群主、QQ 群管理员身份本身不会自动获得网站管理权限。

保留原来的 `BOT_FEED_TOKEN`、PandaScore 配置。然后在项目根目录运行：

```bash
npm run backup
npm run init-db
pm2 restart prg-cs2-bet-new --update-env
```

PM2 进程名按实际替换。新的绑定、群关联、指令去重、结算事件表会自动创建。生产库不会被清空。绑定入口位于网站 **个人中心 → 账号设置 → QQ 群竞猜绑定**。

## 2. Windows 更新配置

停止正在运行的机器人任务，替换程序文件，包括新增的 `interactions.js`，保留 `config.json` 和 `data/`。在现有 `config.json` 中增加（注意 JSON 逗号）：

```json
"commandGroupIds": ["123456789", "987654321"],
"eventPort": 3002,
"eventSecret": "换成至少16字符的独立随机字符串"
```

`commandGroupIds` 必须同时包含在原有 `groupIds` 和 Linux 的 `BOT_COMMAND_GROUP_IDS` 中。名单为空 `[]` 则不启用群指令。`eventSecret` 用于验证 NapCat 发来的事件，应与网站令牌及 NapCat HTTP 服务端的 Access Token 分开。

保持 `dryRun: false`。`games` 同时控制自动结算推送的游戏范围；群内 `/prbet 赛程` 显示网站所有已启用、开放竞猜的游戏。管理员 QQ 只在 Linux `.env` 设置，Windows 不决定管理员权限。

## 3. NapCat 两种 HTTP 连接都要保留

| 配置 | 地址示例 | 用途 |
| --- | --- | --- |
| 已有 HTTP 服务端 | `127.0.0.1:3001` | 程序调用 NapCat，发送群消息 |
| 新增 HTTP 客户端 | `http://127.0.0.1:3002/onebot` | NapCat 把收到的群消息/通知上报给程序 |

在 NapCat 网络配置新增 **HTTP 客户端**：

1. 上报地址（URL）填 `http://127.0.0.1:3002/onebot`。
2. `secret`（事件签名密钥）填与 Windows `eventSecret` 完全相同的值。程序验证 OneBot 的 `X-Signature: sha1=...` HMAC 签名；不要把密钥当查询参数拼在 URL 上。
3. 消息上报格式选 **array / 消息段数组**，启用群消息和群成员减少通知上报。
4. 保存并启用；原来的 HTTP 服务端继续启用。

不同 NapCat 版本字段位置可能不同；必须支持签名上报，缺失或不匹配会收到 401。未上报群成员减少通知时，离群成员需通过网站解绑或在群内发送退出指令解除展示关联。端口 3002 只监听 Windows 本机，不需要公网开放。

重新运行 `node run.js` 或启动计划任务。看到“群指令接收地址：http://127.0.0.1:3002/onebot”表示接收端已启动。然后在启用的群里发 `/prbet 帮助`。正常应在数秒内响应，消息量大时会排队。

## 4. 群成员绑定和竞猜

1. 登录 PRBET 网站，在个人中心的账号设置填自己的 QQ 号，点击“生成绑定码”。
2. 用这个 QQ 在启用功能的群发送 `/prbet 绑定 绑定码`。绑定码 10 分钟内有效，只能使用一次，而且必须由生成时填写的 QQ 使用。无需向机器人发送网站密码。
3. 绑定成功即加入当前群的竞猜展示。一个 QQ 只能绑定一个 PRBET 账号，一个账号也只能绑定一个 QQ。
4. 在另一个启用的群里用 `/prbet 加入` 开启该群的操作及赛后展示。账号绑定全局有效，但各群展示关联独立。

| 指令 | 作用 |
| --- | --- |
| `/prbet 帮助` | 查看指令 |
| `/prbet 赛程` | 显示最近 15 场可竞猜比赛的 ID、时间、队伍顺序和 BO |
| `/prbet 竞猜 123 2:1` | 竞猜 #123，第一支队伍 2、第二支队伍 1；重复提交同场即修改 |
| `/prbet 修改 123 0:2` | 修改同一条竞猜 |
| `/prbet 我的` | 在群里展示自己最近 10 条竞猜及已得积分 |
| `/prbet 取消 123` | 开赛前取消自己的竞猜 |
| `/prbet 加入` | 已绑定 QQ 加入当前群的竞猜展示 |
| `/prbet 退出` | 退出当前群的竞猜操作及展示；不删除网站竞猜 |
| `/prbet 解绑` | 解除 QQ 绑定及所有群的展示关联；不删除网站竞猜 |

网站也可以解除绑定，同时撤销尚未使用的绑定码。改绑 QQ 时先在网站解绑，再生成新码。网站与群指令使用同一份竞猜记录，一人一场一条，群内修改会同步反映到网站。网站关闭竞猜、对阵/时间未定或比赛开始后，机器人拒绝提交和修改；取消也必须在开赛前。

加入群竞猜意味着在该群的赛后通知中展示网站用户名、竞猜比分和得分；从网站提交的竞猜也会纳入。未绑定、未加入当前群、结算后才加入的成员不会被补入该场结算消息。群内主动使用“我的”会公开自己的近期竞猜。

## 5. 管理员操作

由 `BOT_ADMIN_QQ_IDS` 中的 QQ 在已启用群内执行，无需绑定网站管理员账号：

| 指令 | 作用 |
| --- | --- |
| `/prbet 关闭竞猜 123` | 关闭该比赛竞猜 |
| `/prbet 开启竞猜 123` | 开启尚未开赛且对阵和时间已确认的比赛 |
| `/prbet 结算 123 2:1` | 录入正式赛果、结算积分并锁定赛果，避免 PandaScore 覆盖 |
| `/prbet 弃权 123 1` | 第一支队伍因对方弃权获胜；填 2 则第二支获胜，所有竞猜 0 分 |

管理指令会直接生效。再次“结算”可修正赛果并重新计算积分；该场历史得分被替换，不是重复累加。操作的群号、QQ、类型、响应和时间保存在 `bot_command_receipts`，保留 30 天供核对。基础管理不包含删用户、删比赛等操作。

## 6. 结算消息与离线恢复

PandaScore 自动结算、网站管理员录赛果、群管理员结算都会生成事件。程序约每 15 秒读取结算事件并排队发送（大量消息会增加延迟），不依赖当日赛程时间窗口：跨日或延迟结束的比赛也可通知。

```text
【比赛结算 · #123】
示例赛事
Team A 2:1 Team B

本群竞猜结果
alice：2:1 · 比分全中 · 本场 2 分（+2）
bob：2:0 · 猜中胜者 · 本场 1 分（+1）
carol：0:2 · 未猜中 · 本场 0 分（+0）
积分已在网站结算，群消息不会重复加分。
```

赛果修正会标“赛果更正”，展示本场最新得分及相对上次结算的差值，例如 `本场 0 分（较上次结算 -2）`。没有关联成员竞猜时仍推送赛果，注明暂无本群成员参与。对长消息分段发送。

**第一次启动群竞猜功能时，以服务器最新结算事件建立起点，不刷屏补发历史赛果。** 之后正常重启会从保存的游标续读停机期间的事件。首次启用期间尚未登录/绑定的成员不会被补入已有结算事件。

新状态记录在 Windows `data/interactions.json`：包含待处理指令、结算游标、发送记录。原日报仍使用 `data/delivery.json`。更新程序时保留两个文件；不要删除它们来尝试重发。服务器恢复了更旧的数据库导致游标超界时会报 409，需要核对备份与状态，不能静默跳过。

NapCat 重复上报同一条消息不会重复改竞猜或重复结算；网站也保存指令回执，网络超时后安全重试原请求。群回复和结算通知在发送前落盘；发送结果不确定则记 `unknown`，不会盲目重发。待处理指令超过 10 分钟失效，避免很久以前的管理指令突然执行；待发消息超过入队后 2 天不再发送，发送记录保留 14 天。

排查日志仍使用原来的 Windows 日志。`data/interactions.json` 的 `deliveries` 可查具体 `sent`、`failed`、`unknown` 状态。只查看，不要在程序运行时手工编辑。401 检查事件 secret / 网站令牌，403 检查 Linux 群白名单，429 等待限流解除。每个 QQ 每分钟最多处理 20 条网站指令，Windows 同一 QQ 的新指令间隔至少 2 秒。
