# QQ 群竞猜、账号绑定和结算推送

在 [README.md](README.md) 的日报推送基础上启用。需要同时配置 Linux 网站、Windows bot 和 NapCat。更新步骤见 README 的「更新已部署版本」。

## 1. Linux 网站

`.env` 增加（多个号码用英文逗号分隔，不加引号）：

```dotenv
BOT_COMMAND_GROUP_IDS=123456789,987654321
BOT_ADMIN_QQ_IDS=管理员QQ号
```

- `BOT_COMMAND_GROUP_IDS`：允许群指令和结算通知的群。为空则功能关闭。
- `BOT_ADMIN_QQ_IDS`：可执行管理指令的 QQ。权限由网站判断，QQ 群主或群管理员身份不自动获得权限。

然后 `npm run backup && npm run init-db && pm2 restart prg-cs2-bet-new --update-env`。迁移会创建绑定、群成员、指令回执和结算事件表，不清空数据。

## 2. Windows bot

`config.json` 增加：

```json
"commandGroupIds": ["123456789"],
"eventPort": 3002,
"eventSecret": "至少16字符的独立随机字符串"
```

`commandGroupIds` 必须同时出现在 `groupIds` 和 Linux 的 `BOT_COMMAND_GROUP_IDS` 中，`[]` 表示不启用。`eventSecret` 与网站令牌、NapCat Access Token 分开生成。`games` 也限定结算推送的游戏范围。

## 3. NapCat 两个 HTTP 连接

| 配置 | 地址 | 用途 |
| --- | --- | --- |
| HTTP 服务端 | `127.0.0.1:3001` | bot 调用 NapCat 发消息 |
| HTTP 客户端 | `http://127.0.0.1:3002/onebot` | NapCat 上报群消息给 bot |

新增 HTTP 客户端：URL 填上表地址；`secret` 与 `eventSecret` 相同（bot 校验 `X-Signature: sha1=...`，不要把密钥拼进 URL）；消息格式选 array（消息段数组）；开启群消息和群成员减少通知上报。签名缺失或不匹配返回 401。3002 只监听本机。

重启 bot，看到 `群指令接收地址：http://127.0.0.1:3002/onebot` 即接收端已启动，在群里发 `/prbet 帮助` 验证。

## 4. 绑定与竞猜

1. 网站 个人中心 → 账号设置 → QQ 群竞猜绑定，填 QQ 号，生成绑定码。
2. 用该 QQ 在启用的群发 `/prbet 绑定 绑定码`。绑定码 10 分钟有效、仅一次、只能由填写的 QQ 使用。
3. 绑定后自动加入当前群。其他群用 `/prbet 加入`。一个 QQ 只能绑定一个账号，反之亦然。

| 指令 | 作用 |
| --- | --- |
| `/prbet 帮助` | 指令列表 |
| `/prbet 赛程 [cs2/valorant] [今天/明天] [页码]` | 可竞猜比赛，每页 15 场 |
| `/prbet 竞猜 123 2:1` | 竞猜 #123，比分按左队:右队；重复提交即修改 |
| `/prbet 修改 123 0:2` | 同上 |
| `/prbet 取消 123` | 开赛前取消竞猜 |
| `/prbet 我的 [待开赛/待结算/已结算] [游戏] [页码]` | 自己的竞猜，每页 10 条 |
| `/prbet 加入` / `退出` | 加入或退出本群竞猜展示 |
| `/prbet 解绑` | 解除绑定及所有群关联 |

游戏可写 `cs2`、`valorant`，或 `csgo`、`val`、`无畏契约`。“今天/明天”按北京时间 00:00–24:00 自然日（与日报 06:00 分界不同）。超过一页时回复末尾给出下一页指令。退出和解绑不删除网站竞猜。

已绑定并加入本群的成员可回复机器人发送的单场比赛消息，发 `2:1`、`2-1` 或 `2：1` 即提交；已有预测则修改同一条记录。支持临赛提醒、赛程更新、仅含一场的日报／预告／赛程查询／我的竞猜、竞猜回执及单场结算通知。识别以实际发出的每条消息为单位，一条含多场比赛时请使用 `/prbet 竞猜 比赛ID 比分` 明确指定。已开赛或结束的比赛仍会拒绝竞猜。

日常播报和提醒不再附带网址，发送 `/prbet 帮助` 可查看网站入口。新版非提醒消息需由更新后的 bot 和服务端产生；旧临赛提醒的引用仍兼容。不要删除 `bot/data/`，其中保存成功发送的消息 ID 与比赛关联，重启后仍可回复。

网站和群指令共用同一份竞猜记录。比赛关闭竞猜、对阵/时间未定或已开赛时拒绝提交。改绑 QQ 需先在网站解绑。

加入本群即同意在结算消息中展示用户名、竞猜比分和得分（含网站提交的竞猜）。结算后才加入的成员不会补入该场消息。

## 5. 管理指令

由 `BOT_ADMIN_QQ_IDS` 中的 QQ 在启用的群执行，立即生效：

| 指令 | 作用 |
| --- | --- |
| `/prbet 关闭竞猜 123` | 关闭竞猜 |
| `/prbet 开启竞猜 123` | 开启（仅限未开赛且对阵、时间已确认） |
| `/prbet 结算 123 2:1` | 录入赛果、结算并锁定，避免被 PandaScore 覆盖；再次执行即修正 |
| `/prbet 弃权 123 1` | 第 1（或 2）队因对方弃权获胜，所有竞猜 0 分 |

修正赛果会替换该场得分，不重复累加。指令回执保存在 `bot_command_receipts`，保留 30 天。

## 6. 结算推送与状态

PandaScore 自动结算、网站后台录入和群管理指令都会产生结算事件。bot 约每 15 秒拉取一次并排队发送，跨日或延迟结束的比赛也会通知。指令回复优先于结算通知。消息格式见 README。

首次启用时以服务器最新事件为起点，不补发历史；之后重启从保存的游标续读。服务器恢复了更旧的数据库导致游标超界时返回 409，需人工核对。

状态保存在 Windows `data/interactions.json`（待处理指令、结算游标、发送记录），日报记录在 `data/delivery.json`。更新时保留两者，运行中不要手工编辑。

- 重复上报不会重复提交或结算；发送结果不确定记为 `unknown`，不自动重发。
- 待处理指令 10 分钟失效；待发消息 2 天后丢弃；发送记录保留 14 天。
- 限流：每个 QQ 每分钟最多 20 条网站指令，Windows 端同一 QQ 间隔至少 2 秒。

| 错误 | 检查 |
| --- | --- |
| 401 | `eventSecret` / NapCat secret 或网站令牌 |
| 403 | Linux `BOT_COMMAND_GROUP_IDS` |
| 409 | 结算游标超界，见上文 |
| 429 | 等待限流解除 |
