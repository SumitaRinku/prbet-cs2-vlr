# 04 · 后端模块详解

后端全部为 CommonJS 模块 + 函数式组织，无 class。入口 `server/index.js`，其余按 config / middleware / routes / services / utils 分层。

## 1. 入口 — `server/index.js`

| 职责 | 说明 |
| --- | --- |
| 环境 | 第一行 `require('dotenv').config()` |
| 数据库 | `ensureDatabase()`：建表/迁移/历史修复/默认管理员 |
| 日志 | `requestLogger`：requestId、方法/路径/状态码/耗时；慢请求与 5xx 带上下文 |
| trust proxy | 默认 1；`TRUST_PROXY=0` 表示直连部署 |
| CORS | `ALLOWED_ORIGINS` 白名单；非 production 放行 `localhost / 127.0.0.1 / [::1]`；白名单外返回 403 错误对象 |
| 路由 | 11 个子路由 + `/api/health`（含 `/api/bot`、`/api/bot-account`） |
| HTML | `serveHtml(file)`：读 `public/` HTML，注入 `{{BEIAN}}`，设置 `Cache-Control: no-store` 并删除条件请求头 |
| 静态 | 显式 HTML 路由 → `express.static` → `/uploads` → `*` 兜底 index.html |
| 错误 | 末尾 `errorLogger`：客户端错误 info、服务端错误 error + errorId，统一 JSON |
| 启动 | `app.listen` 回调启动 `startPandascoreSyncService()` |

`serveHtml` 忽略 `If-None-Match` / `If-Modified-Since`，确保部署后普通刷新也能拿到新 HTML，不会因 304 复用旧的空白页面。

## 2. 配置层 — `server/config/`

- `database.js`：模块加载即打开 `data/database.sqlite`，`foreign_keys = ON`，导出单例。
- `init-db.js`：`ensureDatabase()` 建表、列迁移、弃权回填、主客对调修复、默认管理员（见 03）。
- `bot-schema.js`：`ensureBotSchema(db)` 追加机器人与 `time_confirmed` 列迁移。

## 3. 中间件 — `server/middleware/`

### auth.js

| 函数 | 说明 |
| --- | --- |
| `loadOrCreatePersistedSecret()` | 读取 `data/.jwt_secret`（≥32 字符）；否则生成并 0600 落盘，失败仅告警 |
| `signToken(user)` | 查库取 `{id, username, role, token_version}` 签发 HS256，30 天 |
| `authenticateToken` | 校验 Bearer；用户不存在或 `token_version` 不一致 → 401 |
| `optionalAuth` | 无 token / 校验失败时 `req.user=null` 放行 |
| `requireAdmin` | 非 admin → 403 |

### rateLimit.js

`createRateLimiter({ windowMs, max, message })`：按 `req.ip` 的滑动窗口计数，超限 429 + `Retry-After`；周期清理过期条目。用于 auth（15 分钟 20 次）、bot feed（1 分钟 300 次）、bot-account（1 分钟 10 次）。

### requestLogger.js

生成 8 位 requestId 挂 `req.requestId`；`res.finish` 时输出级别日志，慢于 1s 或 5xx 附带 userId / ip / UA。

### errorHandler.js

- `ApiError(message, statusCode, details)`
- `errorLogger(error, req, res, next)`：400–499 记 info；5xx 记 error + stack，响应 `{error:'Internal server error', errorId, statusCode}`
- `generateErrorId()` / `validationError()` / `handleDatabaseError()`

## 4. 工具层 — `server/utils/`

### scoring.js（纯函数）

`maxScore(format)`、`isValidScore(s1,s2,format)`、`calculatePoints(prediction, match)`、`possibleScores(format)`。积分判定：

```
未 finished → null
is_forfeit → 0
胜者错 → 0
比分完全一致 → maxScore
否则 → 1
```

### settlement.js

- `settleMatch(matchId)`：重算该场全部预测，仅当分数实际变化时写库，返回 `{processed, changed}`。
- `recalculateUserScores()`：清零 + `SUM(points_earned)` 全量回填，总分唯一权威来源。

### validators.js

`validators.{username,password,role,format,score,prediction,integer,positiveInteger,optionalString,email,boolean}` + `validate(schema)` 中间件（写入 `req.validated`）。

### matchValidation.js

`VALID_GAMES / VALID_FORMATS / VALID_STATUSES`；`validateMatchInput`（必填、赛制、状态、ISO 时间）与 `validateMatchReferences`（赛事/队伍存在、不同队、同游戏类型）。

### predictionHistory.js

`recordPredictionHistory(db, prediction, action)`：写入 `prediction_history`，action 为 created / updated / deleted。

## 5. 服务层 — `server/services/`

### pandascoreService.js

模块状态：`timer`、`previewTimer`、`running`、`previewRunning`。

**比赛同步**

| 函数 | 说明 |
| --- | --- |
| `token()` | `PANDASCORE_API_TOKEN \|\| PANDASCORE_TOKEN` |
| `intervalMs()` | 默认 5 分钟，下限 1 分钟 |
| `lookaheadDays()` | 默认 7 天，**上限 7 天** |
| `fetchJson(path, params)` | 手工拼 query；20s 超时；最多 3 次尝试（408/425/429/5xx 退避重试，4xx 其他直接失败） |
| `fetchMatches(gameType)` | 过去 48 小时 ~ 未来 N 天；每页 100、最多 10 页；超页上限直接报错 |
| `upsertTournament / upsertTeam / upsertMatch` | 幂等入库；TBD、弃权、禁用赛事、`result_locked`、主客对调等规则见 07 |
| `pruneExpiredInactiveTournaments` | 删除已禁用、已结束且无预测的 pandascore 赛事 |
| `syncPandascoreMatches(mode)` | 两游戏 `Promise.allSettled`；事务 upsert + 结算；写 `sync_runs` |
| `syncStatus()` | 比赛与预告配置、最近运行（`last_run` / `preview_last_run`） |

**赛事预告（远期，赛事级）**

| 函数 | 说明 |
| --- | --- |
| `serieDisplayName(serie)` | `league.name + serie.full_name`，品牌名重复时去重 |
| `fetchUpcomingSeries(gameType)` | 请求 `/csgo|valorant/series/upcoming`，按 `preview_days` 过滤时间窗，最多 10 页 |
| `syncTournamentPreviews()` | 两游戏并行；按 `external_id` upsert（保留管理员设置的 `is_visible`）并清理未返回项；单游戏失败保留旧预告；写 `sync_runs(mode='preview')` |
| `previewIntervalMs()` | 默认 6 小时，下限 30 分钟（`PANDASCORE_PREVIEW_INTERVAL_MS`） |
| `startPandascoreSyncService()` | 启动比赛同步 + 15 秒后首次预告 + 各自定时器 |

### settings.js

`app_settings` 键值读写：`getSetting` / `setSetting` / `getPreviewDays`（优先级：数据库设置 > `PANDASCORE_PREVIEW_DAYS` > 180，范围 7–365）。

### tournamentTier.js

导出 `TIER_SQL`：`t.tier` 手动值优先；否则按名称推断（Qualifier → 3；CS2 Major / Valorant Masters、Champions → 1；其余 2）。

### botCommands.js

QQ 群指令核心：`issueCode`（一次性绑定码）、`runCommand`（帮助/绑定/退出/解绑/加入/赛程/我的/预测/取消/开竞猜/关竞猜/结算/弃权）、`predict`（代用户落库并复用校验）、`policy`（`BOT_COMMAND_GROUP_IDS` / `BOT_ADMIN_QQ_IDS`）。指令回执写入 `bot_command_receipts` 保证幂等。

### botSettlement.js

`captureSettlement(db, matchId)`：比赛结算变化时生成去重事件，写入 `bot_settlement_state` 与 `bot_settlement_events`，供机器人轮询推送。

## 6. 路由层 — `server/routes/`

端点细节见 [06-API参考](./06-API参考.md)。

### auth.js

注册（bcrypt cost 10）、登录（`bcrypt.compareSync`）、`/me`、`PUT /visibility`（预测公开开关）、`PUT /password`（验证原密码 + `token_version + 1`）。

### matches.js

`HOME_FINISHED_DAYS = 1`；`matchSelect` 模板统一 JOIN 赛事与双侧队伍；`/upcoming` 返回比赛 + 筛选计数 + 赛事导航；`/:id` 附 `possible_scores`；预测提交/取消写 `prediction_history`；`/:id/head2head` 以本场开赛时间过滤，呈现赛前视角。

### tournaments.js

`GET /` 活跃赛事聚合；`GET /previews` 返回 `is_visible = 1` 的 `tournament_previews` 与当前 `preview_days`（必须在 `/:id` 之前注册）；`GET /:id` 赛事 + 全部比赛；`/:id/leaderboard` 赛事榜；`/:id/predictions` 已结束比赛预测流水。

### predictions.js

`GET /my`：全部预测 + 与排行榜同口径的 stats；`GET /history`：预测变更历史（limit ≤200）。

### leaderboard.js

总榜/CSV/赛事榜/用户明细；仅活跃赛事、排除 admin、排除弃权局；CSV 带 UTF-8 BOM。

### images.js

队标安全代理：URL 白名单、内网 IP 拦截、DNS 全记录校验、固定 IP 连接防 rebinding、重定向逐跳校验、2MB / 12s 限制、图片头嗅探、`nosniff` + CSP。

### teams.js

队伍列表（排除 TBD）与详情（stats / tournaments 履历 + placement 名次 / matches）。

### admin.js

全部 `authenticateToken + requireAdmin`。

| 分组 | 关键行为 |
| --- | --- |
| 统计/同步 | `/stats`、`/sync/status`、`PUT /sync/settings`（预告天数）、`POST /sync/previews`、`POST /sync/pandascore` |
| 赛事预告 | `GET /previews`（含已隐藏项，可按 game_type 过滤）、`PUT /previews/:id/visibility`（管理员控制前台显示哪些赛事） |
| 用户 | 创建 / 改角色（默认 admin 不可降级）/ 重置密码 / 删除（默认 admin 不可删） |
| 赛事 | CRUD（name_locked、short_name、tier）、logo 上传（magic bytes，≤2MB）与清除、toggle-active |
| 队伍 | CRUD（有比赛引用时拒绝删除） |
| 比赛 | CRUD、`/result`（写 `result_locked=1` + 结算）、`/forfeit`（1-0 + 0 分）、betting 切换 |
| 预测 | 近 500 条流水、删除后重建总分 |

### bot.js / botAccount.js

- `createBotRouter(db, getToken)`：`Bearer BOT_FEED_TOKEN` 时间恒定比较；`/schedule`（≤10 天窗口、≤500 ids、≤10000 行）、`/command`、`/settlements`（按群白名单 + 游标）。
- `createBotAccountRouter(db, authenticate)`：登录用户查询绑定、生成绑定码、解绑；1 分钟 10 次限流。

### qrcode.js

仅接受 http/https URL（≤512 字符），size 160–640，返回 PNG，缓存 1 天。

## 7. 维护脚本

| 脚本 | 说明 |
| --- | --- |
| `cleanup-pandascore-duplicates.js` | 清理裸 external_id 与规范 id 并存的重复数据；默认 dry-run，`--apply` 落地，自动备份 |
| `backup-db.js` | better-sqlite3 在线备份到 `data/backups/`，默认保留 7 份（`BACKUP_KEEP`） |
| `restore-db.js` | 恢复指定备份，恢复前自动留存 `database.sqlite.before-restore-<ts>` |

## 8. 测试

`node:test` + `assert/strict`，当前 6 个文件、55 个用例：

- `bracket.test.js`：赛程图纯函数（瑞士轮/双败/单败、轮次识别、TBD 可见性）
- `scoring.test.js`：比分合法性、积分规则、弃权、主客对调
- `auth.test.js`：鉴权与会话失效
- `admin-validation.test.js`：管理端输入/关联校验
- `bot.test.js` / `bot-interactions.test.js`：机器人赛程接口、指令幂等、结算推送、消息拆分

运行：`npm test`。
