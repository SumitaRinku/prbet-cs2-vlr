# 04 · 后端模块详解

后端无 class，全部为 CommonJS 模块 + 函数式组织。入口 `server/index.js`，其余按 config / middleware / routes / services / utils 分层。

## 1. 入口 — `server/index.js`

| 职责 | 说明 |
| --- | --- |
| 环境初始化 | `require('dotenv').config()` 第一行加载 `.env` |
| 数据库就绪 | `ensureDatabase()`（建表/迁移/管理员，见 [03-数据库设计](./03-数据库设计.md)） |
| trust proxy | `Number(process.env.TRUST_PROXY)`，默认 1；0 表示不信任代理头（直连部署） |
| CORS | `ALLOWED_ORIGINS`（逗号分隔）配置则白名单校验（无 origin 放行），否则 `cors()` 全开 |
| 路由挂载 | 9 个 `/api/*` 子路由 + `/api/health` |
| HTML 服务 | `serveHtml(file)`：读 `public/` 下 HTML，`{{BEIAN}}` 占位符替换为 ICP 备案链接（`ICP_NUMBER` 未配置则替换为空串） |
| 静态资源 | 显式 HTML 路由 → `express.static` → `app.get('*')` 兜底 index.html |
| 错误处理 | 末尾 4 参中间件：`console.error` + 500 JSON |
| 启动 | `app.listen(PORT, HOST)` 回调中调用 `startPandascoreSyncService()` |

关键函数：

- `beianHtml()` — 生成备案号 `<a>`（值经 `escapeHtmlAttr` 转义；未配置返回空串避免暴露占位符）。
- `serveHtml(file)` — 返回路由 handler：读文件 → 替换 `{{BEIAN}}` → `res.send`；读失败 404。

## 2. 配置层 — `server/config/`

### database.js（连接单例）

```js
const db = new Database(path.join(dataDir, 'database.sqlite'));
db.pragma('foreign_keys = ON');
module.exports = db;
```

模块加载即建连接；`data/` 目录不存在则递归创建。全后端共享同一 `db` 实例。

### init-db.js — `ensureDatabase()`

启动时幂等地完成建表、列迁移、弃权局回填、默认管理员创建（细节见 [03-数据库设计](./03-数据库设计.md)）。支持 `node server/config/init-db.js` 直跑（`require.main === module` 分支）。

## 3. 中间件层 — `server/middleware/`

### auth.js — JWT 鉴权

| 函数 | 签名 | 说明 |
| --- | --- | --- |
| `loadOrCreatePersistedSecret()` | 内部 | 读 `data/.jwt_secret`（≥32 字符复用）；不存在则生成 32 字节 hex 并以 0600 权限落盘；落盘失败仅告警（退化为本进程临时密钥） |
| `getJwtSecret()` | 内部 | `process.env.JWT_SECRET || 持久化密钥`（环境变量优先） |
| `signToken(user)` | 导出 | `{id, username, role}` → HS256 JWT，30 天有效 |
| `authenticateToken` | 导出（中间件） | 解析 `Authorization: Bearer`；失败 401「请先登录 / 登录已过期」；成功写 `req.user` |
| `optionalAuth` | 导出（中间件） | 同上但无 token / 校验失败时 `req.user = null` 放行（游客可看的接口用） |
| `requireAdmin` | 导出（中间件） | `req.user.role !== 'admin'` → 403；须配合 `authenticateToken` 前置 |

### rateLimit.js — 内存滑动窗口限流

| 函数 | 说明 |
| --- | --- |
| `createRateLimiter({ windowMs, max, message })` | 返回 Express 中间件。按 `req.ip` 计数（依赖 trust proxy 正确配置）；超限 429 + `Retry-After` 头；`setInterval` 周期清理过期条目（`unref` 不阻塞退出）。**单进程有效** |

使用点：`routes/auth.js` 的 `authLimiter`（15 分钟 20 次，覆盖 register/login/password，防爆破与批量注册）。

## 4. 工具层 — `server/utils/`

### scoring.js — 比分与积分（纯函数，零依赖）

| 函数 | 说明 |
| --- | --- |
| `maxScore(format)` | 满分：BO1→1，BO5→3，其余→2 |
| `isValidScore(s1, s2, format)` | 双方非负整数、不平局；较大值 === 该赛制取胜局数（BO1=1/BO3=2/BO5=3），较小值 < 取胜局数 |
| `calculatePoints(prediction, match)` | 结算核心（详见下） |
| `possibleScores(format)` | 前端下拉用合法比分枚举：BO1 `[[1,0],[0,1]]`；BO3 `[[2,0],[2,1],[0,2],[1,2]]`；BO5 六种 |

`calculatePoints` 判定顺序：

```
match.status !== 'finished'         → null（未结算）
match.is_forfeit                    → 0（弃权局一律 0 分，已结算）
actualWinner = winner_team_id ?? 比分推断（平局/缺比分 → null）
predicted_winner_id !== actualWinner → 0
比分完全一致（双方都已知）           → maxScore(format)
否则                                → 1（基础分）
```

### settlement.js — 结算与总分重建

| 函数 | 说明 |
| --- | --- |
| `settleMatch(matchId)` | 重算该场已结束比赛的全部预测得分。用 `points_earned IS NOT ?` 的条件 UPDATE **只在分数实际变化时写库**，返回 `{ processed, changed }`，调用方据此决定是否触发全量总分重建。幂等：重复调用结果一致，赛果修正后再次结算也能纠正 |
| `recalculateUserScores()` | 总分唯一权威来源：先 `UPDATE users SET total_score = 0`，再 `SUM(COALESCE(points_earned,0)) GROUP BY user_id` 回填。任何影响得分的写操作后调用 |

## 5. 服务层 — `server/services/pandascoreService.js`

模块级状态：`timer`（setInterval 句柄）、`running`（同步互斥标志）。

| 函数 | 说明 |
| --- | --- |
| `token()` | `PANDASCORE_API_TOKEN \|\| PANDASCORE_TOKEN` |
| `intervalMs()` | `PANDASCORE_SYNC_INTERVAL_MS`，下限 60s，默认 5 分钟 |
| `lookaheadDays()` | `PANDASCORE_SYNC_LOOKAHEAD_DAYS`，**上限硬编码 7 天**，默认 7 |
| `statusOf(match)` | PandaScore status → 内部 status（not_started→upcoming，running→ongoing，canceled/cancelled→cancelled，postponed→postponed，兜底 upcoming） |
| `formatOf(match)` | `number_of_games` ≥5→BO5，≤1→BO1，否则 BO3 |
| `stageFromMatch(match)` | 从 `match.tournament` 取阶段 `{name, slug, external_id}` |
| `teamFromOpponent(opponent)` | opponents[i] → 队伍字段映射（null = 未定） |
| `ensureTbdTeam(gameType, now)` | 取/建该游戏类型的 TBD 占位队（`external_id = '<game>:__tbd__'`），幂等回填 logo |
| `scoreFor(match, teamExternalId)` | 从 `match.results[]` 按 team_id 取该队得分 |
| `findOrUpgradeExternalId(table, canonicalId, gameType, now)` | external_id 规范化兼容：规范 id → 裸 id 逐级查找并原地升级（详见 [03](./03-数据库设计.md)） |
| `fetchJson(pathname, params)` | HTTP 层：**手工拼 query**（逗号必须字面量，URLSearchParams 会编码成 %2C 导致 PandaScore 400）；`AbortController` 超时（默认 20s）；非 2xx **重试一次**（间隔 2s，吸收瞬时 400/500）；仍失败抛含状态码与响应体的 Error |
| `fetchMatches(gameType)` | 分页拉取（每页 100、最多 10 页、`range[begin_at]` 过去 1 天 ~ 未来 N 天、按 begin_at 排序），行上附加 `__gameType` |
| `upsertTournament(match, now)` | 外部 id = `<game>:<serieId \|\| leagueId>`；展示名拼 `league.name + serie.full_name`（去重防止品牌名重复）；存在则 UPDATE（**name_locked=1 时不覆盖名称**，begin_at/end_at/logo COALESCE，**手动上传的 `/uploads/%` logo 不被同步覆盖**），否则 INSERT（新同步赛事 `is_active=0`、`name_locked=0`，待管理员启用） |
| `upsertTeam(team, gameType, now)` | 规范 id → 按名+游戏兜底认领（回填 external 字段）→ 新建 |
| `upsertMatch(match, now)` | **同步核心**（详见 [07-核心业务流程](./07-核心业务流程.md)）：TBD 占位、弃权局（canceled+winner → finished+1-0+is_forfeit）、赛事禁用跳过、betting_enabled 三态维护、返回 `{id, finished, settle}` |
| `pruneExpiredInactiveTournaments(now)` | 删除「已结束 + 已禁用 + **无任何预测**」的 pandascore 赛事（有预测的必须保留，外键级联会抹掉用户得分明细） |
| `syncPandascoreMatches(mode)` | 同步主流程（详见 [07](./07-核心业务流程.md)）；`running` 互斥；写 `sync_runs` 审计；返回统计对象 |
| `syncStatus()` | 同步配置与最近一次运行记录（admin/stats 与 /sync/status 用） |
| `startPandascoreSyncService()` | `PANDASCORE_SYNC_ENABLED=false` 或无 token 则不启动；否则启动即跑一次（mode='startup'）+ `setInterval` 定时（mode='scheduled'） |

## 6. 路由层 — `server/routes/`

> 端点级参数/响应细节见 [06-API参考](./06-API参考.md)，此处只讲模块内关键逻辑与私有函数。

### auth.js — `/api/auth`

- `usernameRegex = /^[a-zA-Z0-9_]{3,20}$/`；密码 ≥ 6 位。
- `authLimiter`：15 分钟 / IP / 20 次，挂 register、login、password。
- 注册：bcrypt cost 10；`SQLITE_CONSTRAINT_UNIQUE` → 400「用户名已存在」。
- 登录：`bcrypt.compareSync` 校验后签发 token，返回脱敏 `safeUser`。
- `/me`：按 `req.user.id` 回查（id/username/role/total_score/created_at）。
- `/password`（PUT）：验证原密码后更新（仍走 authLimiter，防拿 token 后暴力试原密码）。

### matches.js — `/api/matches`（最大的用户侧路由）

私有构件：

| 名称 | 说明 |
| --- | --- |
| `HOME_FINISHED_DAYS = 1` | 首页「已结束」回看窗口（天） |
| `HOME_PHASE_SQL` | SQL 片段：status + `datetime(match_time)` 推导展示相位 finished/ongoing/upcoming（upcoming 但已过开赛时间 → 视作 ongoing） |
| `NOT_TBD` | `t1.name <> 'TBD' AND t2.name <> 'TBD'`，列表/详情统一排除未定对阵 |
| `isTbdMatch(match)` | 按 team1/team2 id 查是否含 TBD 队（预测提交前校验） |
| `matchSelect(where)` | 比赛 SELECT 模板：JOIN tournaments + 双侧 teams，附 tournament_name/logo、双侧队伍名/短名/logo、prediction_count |

路由：

- `GET /` — 通用列表（status/game_type/tournament_id 筛选，limit 200，按 match_time 升序）；登录用户额外回填 `user_prediction`。
- `GET /upcoming` — **首页专用聚合**：一次返回 `matches` + `filters`（status_counts、tournaments 导航〔含各相位计数、下一场时间〕、finished_window_days）。排序：ongoing → upcoming（时间升序）→ finished（时间倒序）。每行附 `display_status`。
- `GET /:id` — 详情 + `possible_scores`（合法比分枚举）+ `user_prediction`。
- `GET /:id/predictions` — 已结算比赛的公开预测明细（按得分降序，含 `predicted_winner_id` / `predicted_winner_name`）。
- `POST /:id/predictions` — 提交/更新预测（校验链见 [02](./02-系统架构.md) 流程图）。
- `DELETE /:id/predictions` — 开赛前取消。
- `GET /:id/head2head` — 私有 `recentFor(teamId)`（近 10 场，排除本场与弃权，输出对手/胜负/比分）+ `recordOf`（W-L 汇总）+ 交手记录（近 10 场，视角对齐到本场 team1/team2）。两组查询都带 `AND m.match_time < 本场开赛时间` 过滤——**呈现「赛前视角」**：比赛结束后回看，近况与交手仍只统计该场开赛前的对局。

`matchSelect` 附加 `tour.short_name tournament_short_name`（赛事简称，随所有比赛行返回）。

### tournaments.js — `/api/tournaments`

- `matchRows(tournamentId)` — 赛事全部比赛 + 双侧队伍信息 + prediction_count + correct_prediction_count。
- `GET /` — 活跃赛事聚合列表（match/finished/ongoing/upcoming/unfinished 计数 + prediction_count；`status=finished/ongoing` 用 HAVING 过滤）。
- `GET /:id` — 赛事详情 + matches（赛程图数据源）。
- `GET /:id/leaderboard` — 赛事榜（排除 admin 用户与弃权局，按 total_score → success_rate → prediction_count）。
- `GET /:id/predictions` — 赛事内已结束比赛的预测流水。

### predictions.js — `/api/predictions`

- `GET /my` — 当前用户全部预测（JOIN 比赛/队伍/赛事全字段，含 `tournament_id`、双侧队伍 `id`，供分享卡与详情跳转取数）+ stats 汇总（total/settled〔排除弃权〕/points/correct）。

### leaderboard.js — `/api/leaderboard`

私有构件：

| 名称 | 说明 |
| --- | --- |
| `LEADERBOARD_SELECT` | 榜单 SELECT 模板：total_score（排除弃权局）、prediction_count（已结算）、total_predictions、success_rate（%） |
| `pageParams(query)` | page ≥1，page_size 1–100 默认 20 |
| `runLeaderboard(where, params, page, pageSize)` | 计总数 + 分页查询 + 计算 `rank`（跨页正确：offset+index+1） |
| `escapeCsv(value)` | CSV 字段转义（含引号/逗号/换行加双引号） |

路由：`GET /`（总榜，可 game_type）、`GET /export`（CSV，带 UTF-8 BOM 供 Excel 识别，可 game_type/tournament_id）、`GET /tournament/:id`、`GET /users/:id/details`（单用户得分明细 + summary 汇总）。

### images.js — `/api/images`（logo 安全代理）

| 函数 | 说明 |
| --- | --- |
| `isKnownTeamLogo(url)` | 白名单：url 必须存在于 teams.logo_url 或 tournaments.logo_url |
| `isPrivateIp(ip)` | 拦截内网/回环/链路本地（含云元数据 169.254.169.254）/CGNAT/IPv6 私有与 IPv4 映射地址；解析不出合法 IP 按危险处理 |
| `resolvePublicAddress(hostname)` | `dns.lookup({all:true})` 校验**全部** A/AAAA 均为公网地址，返回首条 |
| `sniffImageType(body)` | PNG/JPEG/GIF/WEBP 文件头嗅探（源站 content-type 缺失/不规范时兜底） |
| `fetchImage(url, redirects)` | 代理主流程：仅 http/https；用**校验过的 IP 自定义 lookup** 建连（防 DNS rebinding，TLS 仍校验原主机名）；重定向 ≤3 跳且**每跳重新公网校验**；大小上限 2MB；超时 12s；content-type 非 image/* 且嗅探失败 → 拒绝（防 XSS 挂站） |

路由 `GET /team-logo?url=...`：白名单 + 代理 + 响应头（`Cache-Control: public, max-age=86400`、`X-Content-Type-Options: nosniff`、CSP 禁脚本——SVG 可内嵌脚本）。失败 502。

### teams.js — `/api/teams`

| 函数 | 说明 |
| --- | --- |
| `parseLimit(value, fallback, max)` | 数值规整（防恶意大 limit） |
| `placementForMatches(matches, teamId)` | **名次推断**（纯文本匹配）：有 grand final/final 决赛记录 → 胜者「冠军」负者「亚军」；有 semifinal → 「四强」；quarterfinal → 「八强」；否则「已参赛/待确认」 |
| `teamSummary(row)` | 队伍脱敏输出 |

路由：

- `GET /` — 队伍列表（排除 TBD；可 game_type、q 关键词 LIKE；聚合已赛场次/胜场/未赛场次/最近比赛时间；有战绩优先）。
- `GET /:id` — 队伍详情四件套：`stats`（总胜率）、`tournaments`（赛事履历 + placement 名次 + 胜率）、`matches`（近期比赛）、`team`。`match_limit`/`tournament_limit` 可调（上限 100/50）。

### admin.js — `/api/admin`

`router.use(authenticateToken, requireAdmin)` — **全路由需管理员**。

私有构件：

| 名称 | 说明 |
| --- | --- |
| `parseLimit(value, fallback=300)` | 上限 1000 |
| `applyTournamentActiveState(tournamentId, isActive)` | 启用：重开该赛事未来未开始比赛的 betting；禁用：关闭全部未结束比赛 |
| 赛事 logo 上传 | `TOURNAMENT_LOGO_DIR = data/uploads/tournament`；`PUT /:id/logo` 用 `express.raw`（image/* 直传，≤2MB）+ magic bytes 嗅探格式，落盘为 `<id>.<ext>` 并清理旧文件；`DELETE /:id/logo` 清除后回退名称匹配 logo。上传 logo 存 `/uploads/` 本地路径，同步不会覆盖（见 upsertTournament） |

管理能力（分组）：

- **统计**：`GET /stats`（计数 + syncStatus）、`GET /sync/status`、`POST /sync/pandascore`（手动同步）。
- **用户**：列表 / 创建（role 可选）/ 改角色（**不能降级默认 admin**）/ 重置密码 / 删除（**不能删默认 admin**，删后重算总分）。
- **赛事**：列表（含禁用）/ 创建（name_locked=1，可带 short_name）/ 更新（传 name 即锁定名称；`short_name` 未传保留、传空串清除、非空覆盖；is_active 变化联动 betting）/ toggle-active / **logo 上传与清除** / 删除（**有比赛拒绝**）。
- **队伍**：列表（limit 1000）/ 创建 / 更新 / 删除（**有关联比赛拒绝**）。
- **比赛**：列表（game_type/status/limit 筛选）/ 创建 / 更新（**置 finished 必须已有完整赛果**——引导走 /result；状态跳变 finished 时结算+重建总分）/ **`PUT /:id/result`**（录比分：isValidScore 校验 → 推导胜者 → 事务更新+settleMatch+recalculate）/ **`PUT /:id/forfeit`**（弃权：1-0+is_forfeit+0 分结算）/ toggle betting / 删除（删后重算总分）。
- **预测**：列表（近 500 条全字段）/ 删除（重算总分）。

### qrcode.js — `/api/qrcode`（分享图二维码）

- `GET /?text=<url>&size=<n>`：`qrcode` 包生成 PNG buffer 返回（`Cache-Control: max-age=86400`）。
- 防滥用约束：`text` 必填且 ≤512 字符、必须是**合法 URL 且协议为 http/https**（`new URL` 解析 + 白名单）；`size` 钳制在 160–640（默认 320）。
- 存在动机：前端 canvas 合成分享图需要同源二维码图片，跨域图片会污染 canvas 无法 `toDataURL`。

## 7. 维护脚本 — `scripts/cleanup-pandascore-duplicates.js`

一次性数据修复（历史裸 external_id 与规范 id 并存）。特性：

- **默认 dry-run**；`--apply` 才写库，`--no-backup` 跳过备份。
- 自动备份：`data/database.sqlite.backup-<ISO时间戳>`（`COPYFILE_EXCL` 防覆盖）。
- 主流程 `cleanup()`（单事务）：找重复比赛对（old 裸 id ↔ new `<game>:<id>`）→ `migratePrediction`（预测迁移/合并，胜者 id 重映射）→ 删旧比赛 → 删空旧赛事 → 删无引用旧队伍 → `recalculatePredictionsAndScores()`（重算全部预测分与总分）。
- 输出前后 `summarize()` JSON 对比。
