# 08 · 部署与运维

## 前置要求

- Node.js ≥ 20（`engines` 约束；用到内置 `fetch`）
- PandaScore API Token（<https://dashboard.pandascore.co> 获取）
- 构建 better-sqlite3 原生模块需要编译工具链（Linux 上 `build-essential` + `python3`）

## 本地运行

```bash
npm install          # 安装依赖（better-sqlite3 需编译环境）
npm run init-db      # 建表 + 迁移 + 创建默认管理员
npm start            # 启动，默认 http://127.0.0.1:3000
```

> Windows 下若 `npm install` 因 better-sqlite3 编译失败，可先安装 Visual Studio Build Tools；或确认 Node 版本与预编译二进制匹配。

访问入口：

| 地址 | 说明 |
| --- | --- |
| <http://localhost:3000> | 首页（比赛列表） |
| <http://localhost:3000/tournaments.html> | 赛事回看 |
| <http://localhost:3000/leaderboard.html> | 排行榜 |
| <http://localhost:3000/profile.html> | 个人中心 |
| <http://localhost:3000/teams.html> | 队伍中心 |
| <http://localhost:3000/admin/> | 管理后台 |
| <http://localhost:3000/api/health> | 健康检查 |

默认管理员：

- 用户名：`admin`（可用 `ADMIN_USERNAME` 自定义）
- 密码：`ADMIN_PASSWORD` 指定；否则**首次初始化随机生成并打印在控制台（仅显示一次）**
- 登录后可在「个人中心」修改密码

首次启动若 `.env` 配置了 Token，会立即执行一次同步（mode=startup）并每 5 分钟定时同步；同步进来的赛事默认 `is_active=0`，需到管理后台启用后才在前台出现。

## 环境变量（.env，根目录，勿提交）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址。默认只允许本机 Nginx 反代访问；无反代直连部署才设 `0.0.0.0` 并同时设 `TRUST_PROXY=0` |
| `TRUST_PROXY` | `1` | 信任的反代层数。单层 Nginx 为 1；直连部署 0；前面还有 CDN 按层数调大 |
| `NODE_ENV` | — | production / development |
| `JWT_SECRET` | 自动生成 | JWT 密钥。留空时自动生成并持久化到 `data/.jwt_secret`（0600 权限，重启不掉线）；生产建议显式指定 |
| `ALLOWED_ORIGINS` | 全开 | CORS 白名单，逗号分隔；配置后只允许这些来源 |
| `ADMIN_USERNAME` | `admin` | 默认管理员用户名 |
| `ADMIN_PASSWORD` | 随机 | 留空则初始化时随机生成并打印一次 |
| `ICP_NUMBER` | — | ICP 备案号，注入 footer（生产必填，否则不显示） |
| `ICP_LINK` | 工信部备案页 | 备案号链接 |
| `PANDASCORE_API_TOKEN` | — | PandaScore Token（**必填**，否则无法同步；兼容旧名 `PANDASCORE_TOKEN`） |
| `PANDASCORE_BASE_URL` | `https://api.pandascore.co` | API 基址 |
| `PANDASCORE_SYNC_ENABLED` | `true` | 设 `false` 关闭定时同步 |
| `PANDASCORE_SYNC_INTERVAL_MS` | `300000` | 同步间隔（下限 60000） |
| `PANDASCORE_SYNC_LOOKAHEAD_DAYS` | `7` | 向前查看天数（**代码上限 7 天**） |
| `PANDASCORE_SYNC_RESULTS` | `true` | 设 `false` 关闭已结束比赛赛果同步 |
| `PANDASCORE_REQUEST_TIMEOUT_MS` | `20000` | 单次请求超时 |

`.env` 示例：

```bash
PORT=3000
HOST=127.0.0.1
TRUST_PROXY=1
NODE_ENV=production
JWT_SECRET=请替换为随机长字符串
ALLOWED_ORIGINS=https://your-domain.example
ICP_NUMBER=豫ICP备XXXXXXXX号
PANDASCORE_API_TOKEN=你的PandaScoreToken
PANDASCORE_SYNC_ENABLED=true
PANDASCORE_SYNC_INTERVAL_MS=300000
PANDASCORE_SYNC_LOOKAHEAD_DAYS=7
PANDASCORE_SYNC_RESULTS=true
PANDASCORE_REQUEST_TIMEOUT_MS=20000
```

## 生产部署（Linux + Nginx + PM2）

```bash
# 1. 基础环境
sudo apt-get update
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs build-essential python3

# 2. 应用
cd /home/admin/repo/prg_cs2_bet_new
npm install
npm run init-db
npm run sync:pandascore          # 首次灌数据

# 3. 进程守护
npm install -g pm2
pm2 start server/index.js --name prg-cs2-bet-new
pm2 save
pm2 startup
```

防火墙——**只开放 80/443，绝不对公网开放 3000**：

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# 若以前开过 3000，删掉：
sudo ufw delete allow 3000/tcp
```

原因：Node 默认只监听 `127.0.0.1`，公网直连 Node 会绕过反代并可伪造 `X-Forwarded-For` **绕过登录限流**。

Nginx 反向代理（配 HTTPS）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## 数据与备份

| 路径 | 内容 | 说明 |
| --- | --- | --- |
| `data/database.sqlite` | 全部业务数据（用户/赛事/队伍/比赛/预测/同步记录） | **核心备份对象**；清理脚本会自动生成 `.backup-<时间戳>` 副本 |
| `data/.jwt_secret` | 持久化 JWT 密钥 | 删除会导致全体用户重新登录（显式配置 `JWT_SECRET` 则不受影响） |
| `.env` | 全部敏感配置 | 已 gitignore |

备份建议：定时 `sqlite3 data/database.sqlite ".backup ..."` 或直接文件复制（低写入频率下安全），同时保留 `.env` 与 `data/.jwt_secret`。

## 安全要点清单

| 项 | 措施 |
| --- | --- |
| 密码存储 | bcrypt 哈希（注册/重置 cost=10，默认管理员 cost=12） |
| JWT | HS256 + 30 天；密钥 `JWT_SECRET` 优先，否则 0600 权限落盘持久化；校验固定 `algorithms: ['HS256']` 防算法混淆 |
| 暴力破解 | 登录/注册/改密共用每 IP 15 分钟 20 次限流；改密需验证原密码 |
| IP 伪造 | 默认只监听 127.0.0.1 + trust proxy=1；公网直连被拓扑性阻断 |
| CORS | `ALLOWED_ORIGINS` 白名单（无 origin 放行兼容同源/curl） |
| Logo 代理 SSRF | 白名单（仅库内 URL）+ 内网 IP 全量拦截 + DNS 全记录校验 + 固定 IP 连接防 rebinding + 重定向逐跳校验 + 大小/超时限制 |
| 代理内容安全 | 仅放行图片（content-type + 文件头嗅探）+ `nosniff` + CSP 禁脚本（防 SVG XSS） |
| XSS | 前后端输出统一 `escapeHtml`；HTML 属性转义（备案号注入） |
| SQL 注入 | 全部 prepared statement 参数绑定；动态片段（where/having）仅由白名单值拼接 |
| 敏感文件 | `.env`、`data/` 在 `.gitignore`；备案号真实值不进 git 历史（`{{BEIAN}}` 占位符） |

## 运维 playbook

### 同步异常排查

1. `GET /api/admin/sync/status`（或后台「同步」Tab）看 `configured` / `last_run`。
2. `sync_runs.message` 含失败详情；「全部游戏拉取失败」多为 Token 失效或网络；「部分失败」会自动重试吸收抖动。
3. 手动 `POST /api/admin/sync/pandascore` 或 `npm run sync:pandascore` 复现。
4. 常见坑：`PANDASCORE_SYNC_LOOKAHEAD_DAYS > 7` 无效（代码钳制）；改了 `.env` 需重启进程。

### 积分 / 排行榜不一致

- 任何怀疑积分漂移的场景：管理员对涉事比赛重新录一次赛果（`PUT /admin/matches/:id/result`），事务内自动 `settleMatch + recalculateUserScores` 全量自愈。
- 删除预测/比赛/用户后的总分由对应路由自动重建，无需手工干预。

### 赛果录入错误

- 直接重录 `/result`（幂等）；若 PandaScore 侧后来也给出正确赛果，下次同步会覆盖并重新结算。

### 升级 / 重启

- `git pull` → `npm install` → 重启 PM2。启动时 `ensureDatabase()` 自动完成列迁移与弃权局回填，无需手工迁移。
- JWT 密钥持久化，正常重启不掉登录态。

### 单实例约束（扩展前必读）

限流（内存 Map）、同步互斥（模块级 `running`）、定时器均为**单进程设计**。若未来 PM2 cluster / 多实例部署，需把限流与同步互斥迁到共享存储（如 Redis），否则限流可被绕过、同步会重复执行。
