# 07 · 核心业务流程

本文覆盖：比赛同步、赛事预告、预测提交、积分结算、TBD / 弃权 / 结果锁定、机器人推送。

## 1. 比赛同步（近端）

### 触发方式

| 触发 | mode | 入口 |
| --- | --- | --- |
| 服务启动 | `startup` | `startPandascoreSyncService()` |
| 定时 | `scheduled` | 每 5 分钟（`PANDASCORE_SYNC_INTERVAL_MS`，下限 1 分钟） |
| 管理后台 | `manual` | `POST /api/admin/sync/pandascore` |
| CLI | `cli` | `npm run sync:pandascore` |

前置：`PANDASCORE_SYNC_ENABLED ≠ 'false'` 且配置 Token；手动/CLI 无 Token 时请求会报错。

### 主流程

```
running? ── 是 → { status:'skipped' }
   │ 否
   ▼
INSERT sync_runs(status='running')
   ▼
Promise.allSettled([fetchMatches('cs2'), fetchMatches('valorant')])
   │ 单游戏失败不影响另一个；全部失败 → throw
   ▼
db.transaction:
   for row of rows → upsertMatch(row, now)
      ├─ skipped 不计入
      ├─ 本次新结束 → matchesFinished++
      └─ 当前 finished → settleMatch(id) → changed 则 scoresChanged
   pruneExpiredInactiveTournaments(now)
   scoresChanged → recalculateUserScores()
   ▼
UPDATE sync_runs(status='success'/'failed', message, 计数)
```

部分失败仍记 `success`（CHECK 无 partial），API 返回 `status:'partial'`，详情写入 message。

### fetchMatches

- 窗口：`过去 48 小时 ~ 未来 lookaheadDays()`（默认 7 天，代码上限 7 天）。
- 分页：每页 100，最多 10 页；达到上限仍满页则直接报错，避免假完整。
- `range[begin_at]=start,end` 手工拼 query（逗号不能编码）。
- 单请求 20s 超时；最多 3 次尝试：408/425/429/5xx 指数退避，其他 4xx 立即失败。

### upsertMatch 决策

```
解析 opponents → team1/team2（null = 未定）
   ├─ 解析出 'Unknown Team' → 跳过
   ▼
upsertTournament → 禁用赛事 → 跳过
   ▼
任一方未定 → ensureTbdTeam；两侧都 TBD 是正常未定局
   ├─ 两个真实队伍相同 → 跳过
   ▼
status / format / winnerId
   ├─ cancelled + 有胜者 + 无 TBD → 弃权：finished、1-0、is_forfeit
   ▼
已有记录：
   ├─ result_locked=1 → 只补阶段元数据，不覆盖赛果
   ├─ 主客队顺序翻转 → 对调该场预测比分
   ├─ betting 三态：不能下注→0；wasTbd→1；否则沿用现值
   └─ 比分/胜者 COALESCE 更新
无记录 → INSERT
```

## 2. 赛事预告同步（远期）

### 触发

| 触发 | 频率 | 入口 |
| --- | --- | --- |
| 服务启动 | 启动后 15 秒 | `startPandascoreSyncService()` |
| 定时 | 默认 6 小时（下限 30 分钟） | `PANDASCORE_PREVIEW_INTERVAL_MS` |
| 管理后台 | 手动 | `POST /api/admin/sync/previews` |

### 流程

```
previewRunning? → 跳过
   ▼
INSERT sync_runs(mode='preview', status='running')
   ▼
Promise.allSettled([fetchUpcomingSeries('cs2'), fetchUpcomingSeries('valorant')])
   │ 请求 /series/upcoming，每页 100，最多 10 页
   │ 过滤：begin_at ≤ now + preview_days；已结束的丢弃
   ▼
db.transaction:
   对每个成功的游戏：按 external_id upsert（保留管理员设置的 is_visible）
   → 删除该游戏本轮未返回的旧预告
   （失败的游戏保留旧预告，避免整块消失）
   ▼
UPDATE sync_runs(success, message='赛事预告更新 N 项（未来 D 天）')
```

- `preview_days` 来自 `app_settings`（管理后台设置），默认 180，范围 7–365。
- 管理员可在后台「预告」页签逐项显示/隐藏；前台 `GET /tournaments/previews` 仅返回 `is_visible = 1` 的赛事。
- 预告只展示赛事名/起止时间，不创建比赛、不参与积分与回看。
- 管理后台与前台状态分别读取 `last_run`（比赛）和 `preview_last_run`（预告）。

## 3. 预测提交

```
POST /api/matches/:id/predictions
  1. authenticateToken
  2. 比赛存在；非 TBD；status=upcoming；betting_enabled；未开赛
  3. 胜者 ∈ {team1_id, team2_id}
     isValidScore(s1,s2,format) 且比分方向与胜者一致
  4. UNIQUE(user_id, match_id) 命中 → UPDATE，否则 INSERT
  5. 写 prediction_history（created / updated）
```

取消：`DELETE /api/matches/:id/predictions`，同样限制 upcoming + 未开赛，并写 `deleted` 历史。

## 4. 积分结算

### 规则（`scoring.calculatePoints`）

| 情形 | points_earned |
| --- | --- |
| 未 finished | NULL |
| is_forfeit | 0 |
| 胜者错 | 0 |
| 胜者对、比分不完全一致 | 1 |
| 胜者对且比分完全一致 | BO1=1 / BO3=2 / BO5=3 |

胜者优先 `winner_team_id`；缺失时回退比分推断，仍无法确定则保持 NULL。

### settleMatch / recalculateUserScores

- `settleMatch` 只在该场分数实际变化时写库，返回 `{processed, changed}`。
- `recalculateUserScores` 先清零再按 `SUM(points_earned)` 回填，`users.total_score` 永不增量累加。
- 结算后若机器人已启用，`captureSettlement` 生成去重事件供群推送。

### 触发点

| 场景 | 动作 |
| --- | --- |
| 同步发现比赛结束 / 赛果修正 | `settleMatch` → 有变化才重建总分 |
| 管理员录赛果 `/result` | 事务：更新 + 锁定 + 结算 + 重建 |
| 管理员标记弃权 `/forfeit` | 同上（0 分） |
| 管理员改状态 finished | 仅状态跳变时结算 |
| 删除比赛 / 预测 / 用户 | 重建总分 |
| 启动修复弃权局 / 主客对调 | 逐场结算 + 重建 |

## 5. TBD（未定对阵）

| 环节 | 行为 |
| --- | --- |
| 同步 | 缺失一方用占位队（每 game_type 一条，`<game>:__tbd__`）顶替；两侧 TBD 不跳过 |
| betting | TBD 一律关闭 |
| 对阵确定 | `wasTbd` 检测 → 自动重新开放 betting |
| 前台列表 | SQL 排除含 TBD 的比赛；完整结构交给赛程图 |
| 预测 | 提交时二次校验 TBD → 400 |
| 机器人 | 开竞猜指令要求非 TBD 且时间已确认 |

## 6. 弃权局

PandaScore 对弃权局返回 `canceled + winner_id`。统一策略：**1-0 记录、is_forfeit=1、finished、0 分结算**。

- 同步自动识别；管理员可手动 `/forfeit`。
- `betting_enabled=0`；所有预测 0 分且不挂起。
- 胜率 / H2H / 队伍履历 / 榜单得分率均过滤 `is_forfeit=0`。
- 启动时回填历史弃权局（幂等）。

## 7. 结果锁定

管理员通过 `/result` 或 `/forfeit` 录入后：

```
matches.result_locked = 1
   ▼
PandaScore 后续同步只更新 stage_name/stage_slug/stage_external_id/last_synced_at
   ▼
比分、胜者、状态、弃权标记不会被数据源回滚
```

需要重新接受外部赛果时，由管理员再次手动录入即可。

## 8. 赛事启用 / 禁用

```
禁用：matches.betting_enabled=0（未结束）；前台 SQL 过滤 is_active=0；同步跳过该赛事
启用：重新开放未来未开始的 betting；先补结算一次该赛事已结束比赛
新同步赛事默认 is_active=0，需要在后台启用
```

## 9. 机器人流程（简述）

1. 用户在个人中心生成绑定码 → 群内发送 `绑定 <码>`。
2. 机器人 `schedule` 拉取未来赛程，按时间发送赛程/提醒/赛果。
3. 群内 `预测` / `取消` 通过 `/api/bot/command` 代用户落库（复用同一套校验）。
4. 比赛结算后 `captureSettlement` 写入事件；机器人轮询 `/api/bot/settlements` 并推送到对应群（按入群时间过滤成员）。

## 10. 生命周期示例

```
T-7d   比赛同步拉到近端赛程（TBD 占位）→ 入库；赛事预告单独维护远期赛事
T-2d   对阵确定 → wasTbd 自动重开 betting
T-7d~0 用户/群内提交预测（可改可取消）
T0     开赛 → betting 关闭，预测锁定
T0~2h  同步 finished + 比分 → 结算 → 重建总分 → 机器人事件
T+1d   超出首页「已结束」1 天窗口 → 从首页淡出（赛事页仍可回看）
回看   H2H / 近况按本场开赛前过滤（赛前视角）
修正   管理员重录赛果 → result_locked=1，同步不覆盖，分数自愈
弃权   canceled+winner → 1-0 + 0 分
```
