# 07 · 核心业务流程

本文深入讲解四条主线：PandaScore 同步、预测提交、积分结算、以及 TBD / 弃权两类特殊对局的处理。改这些代码前建议通读。

## 1. PandaScore 同步流程

### 触发方式

| 触发 | mode | 入口 |
| --- | --- | --- |
| 服务启动 | `startup` | `startPandascoreSyncService()`（listen 回调内） |
| 定时 | `scheduled` | `setInterval`（默认 5 分钟，下限 1 分钟） |
| 管理后台手动 | `manual` | `POST /api/admin/sync/pandascore` |
| CLI | `cli` | `npm run sync:pandascore` |

前置条件：`PANDASCORE_SYNC_ENABLED ≠ 'false'` 且配置了 Token，否则定时服务不启动（CLI/手动仍可直接调 `syncPandascoreMatches`，无 Token 时 fetchJson 抛错）。

### syncPandascoreMatches(mode) 主流程

```
running? ── 是 → return { status: 'skipped' }        # 模块级互斥，防重入
   │ 否（置 running=true）
   ▼
INSERT sync_runs (status='running')                    # 审计记录
   ▼
记录基线：teams/tournaments 计数（算增量用）
   ▼
Promise.allSettled([fetchMatches('cs2'), fetchMatches('valorant')])
   │  每游戏独立拉取：单游戏失败不影响其他游戏（部分成功优于全部失败）
   │  全部失败 → throw（sync_runs 记 failed）
   │  部分失败 → console.error，继续入库
   ▼
db.transaction(() => {
    for (row of rows) upsertMatch(row, now)
        ├─ 跳过项不计入 matchesUpserted
        ├─ result.finished（本次从非 finished → finished）→ matchesFinished++
        └─ result.settle（当前为 finished）→ settleMatch(id)
                                          └─ changed>0 → scoresChanged=true
    pruneExpiredInactiveTournaments(now)                # 清理无预测的过期禁用赛事
    if (scoresChanged) recalculateUserScores()          # 只有分数变化才全量重建
})
   ▼
UPDATE sync_runs (status='success', message=摘要, 四项计数)
   │  注意：CHECK 约束无 'partial'，部分失败也记 success，详情进 message，
   │  API 返回 status='partial' 供前端区分
   ▼
return { status, message, tournaments_upserted, teams_upserted, matches_upserted, matches_finished }
finally: running=false
```

### fetchMatches：HTTP 拉取细节

- 窗口：`过去 24 小时 ~ 未来 lookaheadDays() 天`（上限 7 天，配置更大也被钳制）。
- 分页：`page[size]=100`，最多 10 页，返回不足一页即停。
- query 手工拼接——`range[begin_at]=start,end` 的**逗号必须保持字面量**（URLSearchParams 会编码成 `%2C`，PandaScore 报 400 Range Error）。
- 每请求 `AbortController` 超时（默认 20s）；非 2xx 隔 2s **重试一次**（吸收 PandaScore 偶发 400/500 抖动）。

### upsertMatch：单场入库决策树

```
解析 opponents[0]/[1] → team1/team2（null = 未定）
   ├─ 已确定一方解析出 'Unknown Team'（数据异常）→ 跳过 {skipped}
   ▼
upsertTournament → 失败/赛事被禁用 → 跳过 {skipped, disabled}
   ▼
TBD 处理：team1/team2 任一为 null → ensureTbdTeam(gameType) 占位
   ├─ hasTbd → winner=null、比分=null、betting 强制关
   ├─ 两个真实队伍 id 相同（数据异常）→ 跳过
   ▼
status = statusOf(match)          # not_started→upcoming 等
format = formatOf(match)          # number_of_games → BO1/3/5
winnerId：无 TBD 时按 match.winner_id 对号入座
   ▼
弃权判定：status='cancelled' 且有胜者且无 TBD
   └─ isForfeit=true → effectiveStatus='finished'，比分按 1-0
   ▼
赛果同步开关：!hasTbd && status='finished' && PANDASCORE_SYNC_RESULTS≠'false'
   └─ scoreFor(match, externalId) 从 results[] 取分
   ▼
canBet = 赛事活跃 && !hasTbd
   ▼
已有记录（external_id 定位）→ UPDATE：
   bettingEnabled 三态：
     · 不能下注（TBD/赛事禁用/已开赛结束）→ 0
     · wasTbd（此前是 TBD 占位，现在对阵确定）→ 1   # 自动重新开放
     · 常规确定比赛 → 沿用现值                        # 尊重管理员手动开关
   比分/胜者用 COALESCE 更新（不回退已有数据）
   返回 { id, finished: 本次新结束, settle: 当前已结束 }
无记录 → INSERT（betting = canBet && upcoming）
```

### upsertTournament：三层结构与命名

PandaScore 结构：`league`（品牌，如 ESL Pro League）> `serie`（届/赛季，full_name 常为 "Season 21 2026" 甚至只有 "2026"）> `tournament`（阶段）。

- external_id = `<game>:<serieId || leagueId || serie_id || league_id>`
- 展示名 = `league.name + ' ' + serie.full_name`（serie 标签已含品牌名时不重复拼）
- UPDATE 时 `name_locked=1` 则不覆盖名称；新赛事默认 `is_active=0`（**同步进来的赛事默认不展示**，管理员在后台启用后才上首页）

### pruneExpiredInactiveTournaments：清理规则

删除条件：pandascore 来源 + 已禁用 + end_at 已过 + **无任何预测**（有预测的必须保留——外键级联删除会抹掉用户预测记录和得分明细）。

## 2. 预测提交流程（用户侧）

```
用户在首页/详情弹窗选择：胜者（下拉）+ 双方比分（possibleScores 枚举）
   ▼
POST /api/matches/:id/predictions（Bearer JWT）
   ▼ 服务端校验链（全部通过才落库）：
   1. authenticateToken → req.user
   2. 比赛存在
   3. isTbdMatch? → 400「对阵未确定」
   4. status==='upcoming' && betting_enabled → 400「不可预测」
   5. match_time > now → 400「已开始」
   6. predicted_winner_id ∈ {team1_id, team2_id}
   7. isValidScore(s1, s2, format)
   8. 比分大小关系方向 === predicted_winner_id
   ▼
UNIQUE(user_id, match_id) 命中 → UPDATE（可反复修改）
否则 → INSERT（points_earned = NULL 待结算）
```

取消：`DELETE /api/matches/:id/predictions`，同样限 upcoming 且未开赛。

## 3. 积分结算流程

### 积分规则实现（scoring.calculatePoints）

| 情形 | points_earned |
| --- | --- |
| 比赛未 finished | `NULL`（未结算，不写库） |
| is_forfeit（弃权） | `0`（已结算） |
| 胜者预测错 | `0` |
| 胜者对、比分不完全一致 | `1` |
| 胜者对且双方比分完全一致 | 满分（BO1=1 / BO3=2 / BO5=3） |

胜者判定：优先 `winner_team_id`；缺失时回退比分比较（平局/缺比分 → 仍 `NULL`）。

### settleMatch：单场结算（幂等）

```sql
UPDATE predictions
SET points_earned = ?, updated_at = CURRENT_TIMESTAMP
WHERE id = ? AND points_earned IS NOT ?   -- 仅分数实际变化时写库
```

- 返回 `{processed, changed}`；changed=0 时调用方跳过全量总分重建（避免每次同步都全量重算）。
- 幂等性来源：`calculatePoints` 是纯函数，以**当前**赛果重算所有预测——赛果修正后再次结算自动纠正分数。

### recalculateUserScores：总分重建（唯一权威）

```sql
UPDATE users SET total_score = 0;
-- SUM(COALESCE(points_earned,0)) GROUP BY user_id 回填
```

**设计原则：`users.total_score` 是冗余缓存，永远整体重建、绝不增量加减**——增量累加在「赛果修正、预测删除、用户删除、比赛删除」等场景会漂移。

### 结算触发点全集

| 场景 | 结算动作 |
| --- | --- |
| 定时同步发现比赛结束 / 赛果被修正 | 事务内 `settleMatch` → 有变化才 `recalculateUserScores` |
| 管理员录赛果 `PUT /admin/matches/:id/result` | 事务：更新 + settleMatch + recalculateUserScores |
| 管理员标记弃权 `PUT /admin/matches/:id/forfeit` | 同上（0 分结算） |
| 管理员改状态为 finished `PUT /admin/matches/:id` | 仅**跳变**时结算（重复保存不触发） |
| 管理员删除比赛 / 删除预测 / 删除用户 | `recalculateUserScores()` |
| 启动时弃权局回填（init-db） | 事务：逐场 settleMatch + recalculateUserScores |

## 4. TBD（未定对阵）处理

背景：淘汰赛后期对阵取决于前序结果，PandaScore 会先返回无 opponents 的比赛。

| 环节 | 行为 |
| --- | --- |
| 同步入库 | 用占位队（每 game_type 一条，`name='TBD'`，logo `/images/team-tbd.svg`）顶替缺失一方；两侧都 TBD 是正常未定局，**不跳过**（保住赛程图完整结构） |
| betting | TBD 比赛一律 `betting_enabled=0` |
| 对阵确定后 | `wasTbd` 检测 → 自动重开 betting（而非沿用被迫的 0） |
| 前台列表 | SQL `t1.name <> 'TBD' AND t2.name <> 'TBD'` 排除（方案：列表只显示可参与的比赛，完整结构交给赛程图） |
| 预测提交 | `isTbdMatch()` 二次校验 → 400 |
| 赛程图 | 完整渲染 TBD 占位（bracket.js `isTbdMatch` + 占位样式） |

## 5. 弃权局（forfeit）处理

背景：PandaScore 对弃权局返回 `status=canceled` **且带 winner_id**（对手弃权）。旧逻辑记成 cancelled、无比分不结算，预测永远挂着（且超出 1 天回看窗口，同步不会再触及）。

统一策略：**按 1-0 记录、标记 is_forfeit、视作 finished、结算 0 分**。

| 环节 | 行为 |
| --- | --- |
| 同步发现 canceled+winner | `is_forfeit=1`，比分 1-0，status='finished'，betting 关 |
| 管理员手动标记 | `PUT /admin/matches/:id/forfeit`（选胜者） |
| 积分 | `calculatePoints` 对 is_forfeit 直接返回 0（所有预测一律 0 分，已结算不挂起） |
| 启动回填 | init-db 一次性修正历史数据（幂等：修正后 is_forfeit=1 不再命中 WHERE） |
| 统计口径 | 胜率/H2H/榜单/队伍履历全部 `is_forfeit=0` 过滤 |
| 前端展示 | profile 显示「弃权不计分」标签；弃权状态可筛选 |

## 6. 赛事启用/禁用联动

```
管理员禁用赛事（PUT /admin/tournaments/:id 或 toggle-active）
   ▼ applyTournamentActiveState(id, 0)
     UPDATE matches SET betting_enabled=0
     WHERE tournament_id=? AND status != 'finished'
   ▼ 前台效果：is_active=0 → 列表/详情/榜单 SQL 全部过滤，不展示
   ▼ 同步效果：upsertMatch 检测赛事禁用 → 跳过 {skipped, disabled}
     （后续同步不更新其比赛状态与赛果；比分字段 COALESCE 保留旧值）
   ▼ 重新启用：applyTournamentActiveState(id, 1) 重开「未来未开始」比赛的 betting
```

用途：过滤无需竞猜的小型赛事；注意新同步赛事默认 `is_active=0`，需后台启用。

## 7. 一次完整生命周期（时间线示例）

```
T-7d    同步拉到未来 7 天内的赛程（部分 TBD 占位）→ 入库，betting 按规则
T-2d    对阵确定：同步 wasTbd 检测 → 自动重开 betting
T-7d~0  用户注册登录 → 提交预测（胜者+比分）→ 可修改/取消
T0      开赛：status→ongoing（同步或时间推导），betting 关，预测锁定
T0~T2h  比赛结束：同步拉到 finished + results → 写比分/胜者
        → settleMatch（本次新结束）→ 分数变化 → recalculateUserScores
        → 排行榜、profile 状态刷新
T+1d    超出首页「已结束」1 天窗口 → 从 upcoming 列表淡出（赛事页/赛程图仍可回看）
修正    赛果录错：管理员 /result 重录 或 下次同步覆盖 → 重新结算 → 分数自愈
弃权    PandaScore canceled+winner → 1-0 + 0 分；历史数据启动时回填
```
