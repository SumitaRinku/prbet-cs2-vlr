# 05 · 前端模块详解

前端为**原生多页应用**（MPA）：6 个 HTML 入口 + 各自配套脚本，无框架、无构建、无包管理。公共能力收敛在若干全局脚本：`theme.js`（主题）、`tournament-logos.js`（厂牌 logo + 暗色变体）、`shared.js`（认证/API/公共渲染/赛事简称）、`h2h.js`（对阵历史弹窗）、`share.js`（分享图），复杂可视化收敛在 `bracket.js`（纯函数库）。

## 页面与脚本总览

| 页面 | 脚本（按加载顺序） | 职责 |
| --- | --- | --- |
| `index.html` | theme → tournament-logos → shared → h2h → share → bracket → `app.js` | 首页：比赛列表 + 三维筛选（游戏/赛事/状态）+ 登录注册 + 比赛详情弹窗（预测提交、H2H、预测明细）+ 折叠赛程图面板 + 赛事组标题直达回看 + 分享 |
| `tournaments.html` | theme → tournament-logos → shared → h2h → bracket → `tournaments.js` | 赛事列表 → 赛事详情（吸顶阶段导航、赛程图、赛事榜、预测流水），URL 持久化 `?id=` 直达 |
| `leaderboard.html` | theme → tournament-logos → shared → `leaderboard-page.js` | 排行榜：游戏/赛事筛选、分页、CSV 导出、用户得分明细弹窗 |
| `profile.html` | theme → tournament-logos → shared → share → `profile.js` | 个人中心：我的预测卡片（状态筛选、分享）、统计摘要、修改密码 |
| `teams.html` | theme → tournament-logos → shared → `teams.js` | 队伍中心：队伍卡片列表（搜索/游戏筛选/排序）→ 队伍详情（统计、赛事履历、近期比赛） |
| `admin/index.html` | theme → tournament-logos → `admin.js` | 管理后台：比赛/赛事/队伍/用户/预测五个 Tab + 统计与同步面板，模态编辑 |

样式统一在 `public/css/style.css`（CSS 变量 + `html[data-theme]` 切换主题）；图片在 `public/images/`；字体在 `public/fonts/`（MiSans woff2 子集，分享图 canvas 用）。

## 公共模块

### `theme.js` — 主题切换（所有页面，最早加载）

- IIFE 自执行：初始化 `html[data-theme]`（localStorage `theme` 未设置时跟随系统 `prefers-color-scheme`），并同步 `colorScheme`。
- `addToggle()` — 向 `#userPanel`（管理后台为 `#auth`）追加 `#themeToggle` 按钮（太阳/月亮 SVG 图标）。点击切换主题、写 localStorage，并派发 `theme-changed` CustomEvent。
- `shared.js` / `app.js` 的 `renderUser()` 重新渲染用户面板 innerHTML 时会**把 `#themeToggle` 节点重新 append 回来**（避免 innerHTML 覆盖丢按钮）。

### `tournament-logos.js` — 赛事厂牌 logo + 暗色变体（所有页面，先于业务脚本）

- `TOURNAMENT_LOGOS` 表：按赛事名关键词（如 `'esl pro league'`、`'vct masters'`）匹配 `public/images/tournament/` 下的本地文件；Game Changers 显式排除（避免误挂赛区标）；未命中不显示。
- `tournamentLogoUrl(name, gameType)` / `tournamentLogo(...)` — logo 优先级：**管理员手动上传（`/uploads/` 本地文件）> 名称匹配的精选映射**；远端 URL 不使用。
- 暗色变体约定：同目录同名 `-dark` 文件（如 `iem.png → iem-dark.png`）。暗色主题下优先换用变体，404 自动回退原图（`darkVariantMissing` 缓存 + `tournamentLogoError`），原图也失败则移除节点。
- 监听 `theme-changed` 事件：`applyTournamentLogoTheme()` 对已渲染的赛事 logo 即时换源，并调 `applyTeamLogoTheme()` 同步**队标**的暗色版本（PandaScore `dark_mode_image_url`，经 `data-light`/`data-dark` 属性驱动，失败回退亮色、再失败显示 TEAM 占位）。
- 各页 `logoHtml()`/`logo()` 渲染的队标 `<img>` 需带 `data-team-logo`、`data-light`、`data-dark` 属性以接入换源。

### `shared.js` — 认证与跨页共享

引入方式：普通 `<script>`，全局函数直接挂 `window`。

| 导出（window.*） | 说明 |
| --- | --- |
| `sharedState` | `{ token, user }`，初始化自 localStorage |
| `sharedApi(path, options)` | fetch 封装：自动带 `Authorization: Bearer`、JSON 序列化；**401 且非 /auth/** 路径 → 清登录态并抛「登录已过期」（登录/注册的 401 是凭据错误，不触发登出） |
| `renderSharedUser()` | 渲染 `#userPanel`：未登录表单 / 登录态（用户名·角色·积分 + 退出 + 管理员显示后台入口）；重渲染后把 `#themeToggle` 重新挂回 |
| `sharedLogin()` / `sharedRegister()` / `sharedLogout()` | 认证三件套，成功后 `notifyAuthChanged()` |
| `gameName(game)` | game_type → 中文/品牌名 |
| `formatDateTime(value)` | zh-CN 本地化短格式（MM-DD HH:mm） |
| `proxiedLogoUrl(url)` | 相对路径/data URI 直用；远程 URL → `/api/images/team-logo?url=...`（encodeURIComponent） |
| `logoHtml(url, darkUrl)` | `<img>` + `data-light`/`data-dark`/`data-team-logo`（供暗色换源）+ `referrerpolicy="no-referrer"` + onerror 走 `teamLogoError` 降级 |
| `matchPredictionDetailRow(prediction, index, match)` | 预测详情列表单行：名次徽标（前三名高亮）、用户名、选择胜者、预测比分、命中状态、得分 |
| `tournamentNameHtml(name, shortName)` | **赛事简称渲染**：有手动简称（`tournaments.short_name`）时输出 `tn-full`/`tn-short` 双 span，CSS 按「移动端（≤760px）或全名 >16 字符」切换展示简称 |
| `renderMatchPredictionDetail(match, predictions)` | **预测详情卡统一渲染**（主页与回看页共用）：对阵英雄区（队标 + 终场比分）→ 赛事元信息 → 弃权提示（如适用）→ 统计条（参与/命中/命中率/最高加分）→ 排名列表 |

事件协作：`auth-changed` CustomEvent — profile 等页面监听后重新加载数据；`theme-changed` — tournament-logos.js 响应换源。

### `h2h.js` — 对阵历史弹窗（主页与回看页共用）

- `showMatchHead2Head(matchId)` 挂 `window`：请求 `GET /matches/:id/head2head` 后渲染 `#detailModal`（两页均已存在该弹窗骨架）——对阵 hero 区 + 双方「近况」面板（胜率、W-L、逐场胜/负 + 对手 + 比分 + 时间）+「交手记录」列表。
- **运行时适配**：两页全局名不同（index 页是 `api`/`logo`，其余页是 `sharedApi`/`logoHtml`），文件内按 `typeof` 探测取用，实现单文件复用。
- 数据本身是「赛前视角」（服务端按开赛时间过滤，见 [04](./04-后端模块详解.md) matches.js 一节）。

### `share.js` — 竞猜分享图（主页与个人中心共用）

- `sharePrediction(matchId)` 挂 `window`：从宿主页钩子取数据 → 生成 1080×1080 PNG → 弹窗展示（`#shareModal`，懒创建），支持下载按钮 / 移动端长按保存，Esc 关闭。
- **数据钩子**（宿主页实现，share.js 只消费）：
  - `window.getMatchForShare(matchId)` — 返回分享卡需要的 match 结构；
  - `window.getShareContext()` — 返回 `{ user }`（当前登录用户）。
- 渲染管线 `renderShareCard(match, user)`：
  1. `loadFonts()` — FontFace API 加载 `/fonts/MiSans-Medium.woff2`（正文 500）与 `MiSans-Bold.woff2`（标题 700），失败回退 system-ui；
  2. `detectTheme()` — 按 `html[data-theme]` 选双色板（`C_DARK`/`C_LIGHT`，保证浅色底可读）；
  3. 并行加载队标（暗色主题优先 dark 变体，经 `proxiedLogoUrl` 走同源代理）、品牌 logo、`/api/qrcode` 生成的站点二维码（URL 带 `?sharetest` 时跳过，便于测试占位）；
  4. 依次绘制：背景（顶部品牌色条）→ 头部 → 赛事信息（名称/场次/开赛时间）→ **英雄对阵区**（队标 140px + 预测比分 88px 为视觉锚点，被选中队伍金色）→ 结果区（实际比分 + 状态徽章：命中加分 / 待结算 / 未命中 / 弃权不计分）→ 预测人行（用户名 + 总积分）→ 底部（二维码 + 「扫码加入 PRBET」）。
  5. `canvas.toDataURL('image/png')` 输出。
- 文本统一走 `textEllipsis`（按 `measureText` 截断加省略号），超长队名/赛事名不破版。

## 首页 — `public/js/app.js`（约 600 行）

自维护 `state`（token/user/matches/tournaments/game/tournament/status 筛选/filterCounts/bracketCollapsed + `matchesRequestId`、`bracketRequestId` **请求竞态令牌**）。

主要流程：

- `loadAll()` — 并行拉取比赛列表（`GET /matches/upcoming`）与赛程图数据，用 requestId 丢弃过期响应（筛选快速切换时防止旧数据覆盖新数据）。
- 筛选器：游戏（cs2/valorant/全部，localStorage 持久化）、赛事（来自 filters.tournaments，含各相位计数徽标）、状态（all/upcoming/ongoing/finished 计数来自 status_counts）。
- 比赛分组渲染 `renderMatchResults`：按赛事分组（`home-tournament-group`），**组标题是链接**（`/tournaments.html?tournament=<id>`）——点击直达该赛事的回看详情页；标题文字用 `tournamentNameHtml`（自动简称）。
- 比赛卡片 `matchCard(match)`：队标/短名、比分或 VS、时间、赛制、预测人数；已结束比赛附「查看预测详情」按钮；卡片底部「对阵历史」按钮（`showMatchHead2Head`）；有预测时显示「我的预测」条（得分/待结算/弃权标签 + **分享按钮**）。
- 详情弹窗 `showMatchDetail(id)`：比赛信息 + `possible_scores` 驱动的预测表单（胜者 select + 双方比分 select）+ 提交/取消预测。
- `showMatchPredictions(id)` — 已结算比赛的预测详情，直接用 `shared.js` 的 `renderMatchPredictionDetail` 渲染。
- 折叠赛程图面板：当前游戏活跃赛事的 bracket 总览（复用 bracket.js）。
- **分享数据钩子**：`window.getMatchForShare`（从 `state.matches` 找比赛）与 `window.getShareContext`（`{ user }`）——`state` 是模块作用域，通过钩子暴露给 share.js。

注意：`app.js` 内部保留了一份独立 `api()`/`logout()` 实现（与 shared.js 逻辑一致），首页自身闭环；`bracket.js` 渲染所需 `escapeHtml`/`logoHtml` 由页面脚本提供。

## 赛程图管线 — `public/js/bracket.js`（约 1130 行，纯函数）

**设计约束**（文件头注释明确）：不含任何页面状态 / DOM 副作用；顶层只有函数声明与字面量常量；依赖三个**环境全局**：`escapeHtml`、`logoHtml`、`focusTournamentMatch`（由引入页提供）。因此 `node:test` 可直接 require 测试。

### 渲染管线

```
matches[]（GET /tournaments/:id 的 matches，含 stage_name/slug/external_id、双侧队名/比分/状态）
   │ buildTournamentStages(matches)
   ▼
stages[]（按阶段分组：API stage 优先 → 名称归一化 → 日期兜底）
   │ stageDiagram(stage) / stageSections
   ▼
{ format, html }   三种赛制图：
   · swissDiagram       瑞士轮（16 队骨架、3-0/3-1/3-2 晋级桶、轮次列）
   · doubleElimDiagram  双败（UB/LB 泳道、轮次对齐、决赛总览）
   · playoffDiagram     单败淘汰（compact 卡片 + 胜负流向标记）
```

### 关键函数（按管线顺序）

| 函数 | 说明 |
| --- | --- |
| `apiStageFromMatch(match)` | 有 `stage_external_id/slug` 时生成 `00-api-*` key（优先级最高） |
| `normalizeStageName(name)` | 阶段名归一化：瑞士轮 Round N / 淘汰赛 / 四分之一 / 半决赛 / 决赛 / 小组 / Opening / Elimination / Decider → 排序 key + 中文 label |
| `dateStage(match)` | 无阶段信息时按日期分桶（`90-yyyy-mm-dd`） |
| `stageInfo(match)` / `groupMatches(matches)` / `sortTournamentStages(stages)` | 单场阶段判定 → Map 分组（组内按时间排序）→ 阶段排序 |
| `splitRepeatedSwissStages(groups)` | 重复瑞士轮阶段拆分 |
| `detectSwiss16(roundGroups)` + `SWISS_16_SKELETON` | 识别 16 队瑞士轮并补占位骨架 |
| `swissRoundBuckets` / `swissFinalBuckets` / `swissDiagram` | 瑞士轮列布局 + 3-0/3-1/3-2 晋级桶 + 整图 HTML |
| `bracketKind(match)` | 单场归类 `{side: 'upper'/'lower'/'final', round, label, kind}`（正则识别 LB R1/UB QF/SF/F/Grand final 等） |
| `matchesByBracketKind(matches)` | 按 side 分桶 |
| `bracketMatchPosition(match)` / `bracketMatchCompare` | 从 match name 解析显式位置编号（`quarterfinal 2`），**按显式位置排序而非 API 时间序** |
| `collectConnectedMatches(matches, teamSet)` | 连通分量：以队伍集合传播收集相关比赛 |
| `doubleElimRounds(map, side)` / `doubleElimLane` / `doubleElimDiagram` | 双败泳道布局与整图 |
| `playoffGroupsFromMatches(matches)` / `playoffDiagram` | 单败分组与渲染 |
| `isCompactableColumn(matches)` / `computeNarrowFlags(matchGroups)` | **移动端窄列**：整轮「未定（TBD/占位）或已全部结束」的列可收窄；存在活跃列时活跃列全宽、其余收窄；全部可压缩（赛事已完结）时保留最右一列全宽展示最终结果 |
| `bracketWhenChip(match)` | **卡片角标**：进行中 → `LIVE` 红标；未开赛 → 本地时区开赛时间（MM-DD HH:mm）。TBD/占位/已结束不显示。瑞士轮/双败/单败三种卡片共用 |
| `playoffLayout(groups, narrowFlags)` | 单败布局：每列独立宽度（窄列 92/116px，普通 150/160px），连接线按各列实际宽度计算 |
| `bracketTeamState(match, side, flow)` | 队伍行状态：`{finished, won, tone: 'pending'|'won'|'lost', marker}`（流向标记） |
| `buildBracketModel(matches)` | **总入口**：输出 `{format, stages, diagnostics}`（diagnostics 含 inputCount/renderedCount/uniqueRenderedCount，测试断言无损渲染） |
| `buildTournamentStages(matches)` / `tournamentBracketSections(matches)` | 分阶段入口（区分瑞士轮+季后赛、显式轮次等结构） |

双败图的队伍行把流向箭头（↓/→）与比分合并为右对齐整体（如 `↓0`），窄屏收窄时不错位；泳道头部不再单列图例。**双败泳道列宽对齐约定**：窄列旗标由 `doubleElimDiagram` 按「轮次下标」合并 UB/LB 两泳道的比赛统一计算后传入 `doubleElimLane`，保证上下泳道同列同宽；桌面端网格列数跟随 `--de-round-count`（写死 3 列会使 4 轮泳道折行——已修复）；移动端泳道行 `overflow-x:auto` 兜底横向滚动。

## 赛事页 — `public/js/tournaments.js`（约 360 行）

- 列表视图 `tournamentCard`：赛事卡片（logo、游戏 pill、计数徽标、时间范围），标题用 `tournamentNameHtml`（自动简称）。
- 详情视图 `openTournamentPage(id)`：`GET /tournaments/:id` → **吸顶阶段导航**（`tournament-stage-map`：阶段缩略卡片，横向滚动，点击 `openTournamentStage` 展开对应 `<details>` 并补偿 sticky 高度）→ 赛程图（bracket.js）+ 赛事榜（`GET /tournaments/:id/leaderboard`）+ 预测流水切换。
- 详情头部与赛程图卡片同上（进行中红框 LIVE、未开赛卡上方时间角标）。`matchRow(match)`：已结束比赛提供「查看预测详情」+「对阵历史」；未开赛且队伍已定提供「对阵历史」；TBD 显示「等待队伍产生」。
- `showMatchPredictions(matchId)` — 预测详情弹窗，用 `shared.js` 的 `renderMatchPredictionDetail` 渲染；H2H 弹窗来自 h2h.js。
- 视图模式（列表/详情）+ `?id=` URL 持久化（`updateTournamentUrl`），刷新/分享直达。
- `focusTournamentMatch(matchId)` — 滚动定位并高亮某场比赛（bracket.js 环境依赖之一）。
- **回到顶部**：IIFE 创建 `.back-to-top` 悬浮按钮，滚动超过 0.6 屏显示。

## 排行榜页 — `public/js/leaderboard-page.js`（约 230 行）

- 筛选：游戏（总榜）+ 赛事下拉（`loadTournamentOptions`，取活跃赛事）；移动端筛选栏 sticky 置顶。
- `loadLeaderboard()` — 分页表格（`rankIcon` 前三名奖牌徽标、用户名、总分、已结算数、得分率）；`renderPagination` / `goPage`。
- `exportLeaderboard()` — 跳转 `GET /leaderboard/export?...` 下载 CSV。
- `showUserDetails(userId)` — 用户得分明细弹窗（逐条预测：预测比分 vs 实际比分、得分、弃权标记），明细超一页时 `loadMoreUserDetails` 增量渲染；请求失败有专门错误态。

## 个人中心 — `public/js/profile.js`（约 190 行）

- 依赖 shared.js（sharedState/sharedApi/gameName/logoHtml）与 share.js。
- `loadProfile()` — 未登录显示提示；已登录 `GET /predictions/my` 渲染摘要（总预测/已结算/积分/得分率）+ 预测卡片列表（每页 20 条，`loadMorePredictions` 增量加载）。
- `predictionStatus()` — 状态标签：弃权不计分 / 待结算 / 已得分 / 未得分。
- `filteredPredictions()` — 客户端筛选：全部/已结束/待结算/得分/未得分/弃权。
- **分享桥接**：预测卡片带「分享」按钮 → `sharePredictionFromProfile(matchId)`；`window.getMatchForShare` 把预测记录转换为分享卡需要的 match 结构（字段名与 app.js 的赛程 match 对齐，含 `user_prediction`）；`window.getShareContext` 提供 `{ user: sharedState.user }`。
- `changePassword()` — 调 `PUT /auth/password`（校验两次一致、长度 ≥6）。

## 队伍中心 — `public/js/teams.js`（约 150 行）

- `loadTeams()` — `GET /teams`（游戏筛选 + 名称关键词搜索 + **排序**：默认按最近活跃 `recent`，可切换，选择持久化 localStorage），卡片含胜场/负场徽标，整卡链接到 `/teams.html?team=<id>`。
- `openTeamDetail(id)` — `GET /teams/:id`：stats（场次/胜率/未赛）、tournaments 履历（placement 名次、W-L、胜率）、近期比赛列表（对己方视角的比分与胜负标签 `matchResultLabel`）。
- `updateTeamUrl(id)` — `?team=<id>`（另带 `sort` 参数）持久化，刷新/分享直达详情。

## 管理后台 — `public/js/admin.js`（约 700 行）

- 独立 `state`（token/user/game 筛选 + 五类数据列表 + 各类行数上限）与独立 `api()`（401 处理同 shared）。
- **Tab 结构**：`matches / tournaments / teams / users / predictions` 五个 Tab（`ADMIN_TABS`），hash 路由（`#/matches` 等，`initTabFromHash` + `hashchange` 监听）；统计概览与同步面板常驻页面顶部（统计 Tab 不再是独立 Tab）。
- **模态编辑**：`openAdminModal({title, body, onSubmit})` 统一创建/编辑表单弹窗（`createMatch`/`editMatch`/`createTeam`/`editTeam`/`createUser`/`resetPassword`/`setResult`/`setForfeit` 等），`withErrorAlert` 统一错误提示。
- **分页**：每类列表默认渲染 `ROW_PAGE_SIZE`(60) 行，`loadMoreRows` 增量加载。
- 同步面板：状态展示（enabled/configured/interval/last_run）+ 手动触发按钮（`syncNow`）。
- 比赛 Tab：创建/编辑、**录赛果**（比分表单 → `PUT /admin/matches/:id/result`）、**弃权标记**（选胜者 → `PUT /admin/matches/:id/forfeit`）、betting 开关、删除。
- 赛事 Tab：CRUD（含**简称**字段）+ 启用/禁用 toggle（联动该赛事 betting）+ **logo 上传/清除**（读文件为二进制 PUT 到 `/admin/tournaments/:id/logo`，或 DELETE 清除）。

## 静态资源与页面服务

- HTML 由服务端 `serveHtml()` 注入 ICP 备案号后返回（占位符 `{{BEIAN}}`，仓库不含真实备案号）。
- `/js` `/css` `/images` `/fonts` 走 `express.static`；`/uploads`（`data/uploads`）服务管理员上传的赛事 logo。主页页脚提供 GitHub 仓库链接（`site-footer .footer-links`）。
- `tournament_logo/`（仓库根）是厂牌 logo **源素材归档**（cs2/、vlr/），已 gitignore；运行时只使用 `public/images/tournament/`。

## 前端约定

- 所有用户数据插值一律经 `escapeHtml`（各文件自带同名实现）。
- 远程队标一律经 `proxiedLogoUrl` 走后端代理（SSRF/XSS 防护闭环）。
- 登录态持久化：`localStorage.token` + `localStorage.user`；401 统一登出并提示。
- 筛选状态持久化到 localStorage（`gameFilter`、`homeTournamentFilter`、`homeStatusFilter`、`teamSort`、`adminGameFilter`、`theme` 等），刷新还原。
